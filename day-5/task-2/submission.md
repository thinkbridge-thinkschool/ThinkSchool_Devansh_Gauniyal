## What did you learn this session?
`--arch arm64` alone wasn't enough for an Alpine base image -- I needed the musl-specific runtime identifier, or the native SQLite library silently failed to load. Separately, the official base image runs as a non-root user that can't write to its own working directory, which broke SQLite until I redirected it to `/tmp`.

## What would break this?
Publishing with the wrong runtime identifier for the base image's libc (glibc vs musl) crashes the container at startup with no build-time warning -- it only shows up when you actually run it. And since the official image runs as non-root, anything that writes to its own working directory (like SQLite here) fails unless redirected to a writable path.
