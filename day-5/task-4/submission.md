## Notes for mentor
`azure.yaml` (generated by `azd init`, no edit needed): service `quotes-api`, project `QuotesApi`, host `containerapp`, port `8080`. `azd` created its **own** resource group (`rg-task4`) and Container Apps environment (`cae-hvnke3dqrbwrq`) rather than reusing Task 3's `thinkschool-env` -- confirmed directly from the generated Bicep before ever deploying. That collided with a real subscription-wide cap of exactly one Container Apps environment (global, not per-region, confirmed by testing two regions); with explicit approval, Task 3's `thinkschool-rg` was deleted to free the slot (its git deliverables were already committed and unaffected). A second real bug then surfaced: `azd` hardcodes the glibc-targeted `linux-x64` runtime identifier for .NET container builds, which is incompatible with the Alpine (musl) base image copied from Task 2 -- the container pulled and started but crashed with a native-library load error. Fixed by switching `<ContainerBaseImage>` to the glibc-based `mcr.microsoft.com/dotnet/aspnet:10.0` tag. No Dockerfile was used at any point. Real, final `azd up`/`azd deploy` result: `SUCCESS`, live URL `https://quotes-api.orangeforest-e47478db.centralindia.azurecontainerapps.io/`. Real `curl -i .../health`: `HTTP/2 200`, body `{"service":"QuotesApi","machineName":"quotes-api--azd-1786701957-54d897f49d-6fpp6","architecture":"X64","utc":"..."}` -- `X64` confirms this is genuinely amd64 in the cloud, not emulated. Commit hash: this same commit (a commit cannot contain its own hash inside its own tree; see `git log -1` or the GitHub commit view). Subscription/tenant/client IDs are redacted deliberately throughout. These resources will be torn down at end of day, so the live URL will stop responding after that.

## What did you learn this session?
`azd` hardcodes the glibc-targeted `linux-x64` runtime identifier for .NET containers, so an Alpine base image copied from an earlier task will pull and start but crash on its native SQLite library -- a bug invisible until you actually curl the live URL and read real container logs.

## What would break this?
This subscription allows exactly one Container Apps environment total, so `azd` defaulting to creating its own (instead of reusing an existing one) can silently collide with that cap regardless of which region you pick.
